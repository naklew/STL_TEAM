SLT Hybrid v0.4.0 설치
======================

1) SLT 저장소를 clone 또는 pull합니다.

   git clone https://github.com/naklew/STL_TEAM.git
   cd STL_TEAM

2) Codex plugin을 등록/설치합니다.

   codex plugin marketplace add naklew/STL_TEAM --ref main
   codex plugin add sol-luna-team@sol-luna-team

3) 대상 프로젝트에 custom agent/tool bundle을 설치합니다.

   python scripts/slt_setup.py install /path/to/target-project

   이 명령은 다음을 관리합니다.
   - .codex/agents/luna-fast.toml
   - .codex/agents/luna-worker.toml
   - .codex/agents/terra-worker.toml
   - .codex/agents/sol-architect.toml
   - .codex/agents/sol-reviewer.toml
   - .codex/slt-tools/policy_defs.py
   - .codex/slt-tools/contract_guard.py
   - .codex/slt-tools/routing_policy.py
   - .codex/slt-tools/writer_lock.py
   - .codex/config.toml 의 [agents] 설정
   - .codex/slt-team.json 버전/managed-file hash
   - Git worktree-safe info/exclude 설정

   일반 checkout과 linked Git worktree(.git이 파일인 경우) 모두 지원합니다.

4) 설치 readiness를 확인합니다.

   python scripts/slt_setup.py status /path/to/target-project

   status가 0으로 끝나야 named worker delegation을 시작하는 것이 안전합니다.

5) 새 Codex parent 세션을 gpt-5.6-terra / high 로 시작하고 명시적으로 호출합니다.

   $sol-luna-team 이 기능을 구현해줘.

업데이트
========

   git pull
   python scripts/slt_setup.py update /path/to/target-project
   python scripts/slt_setup.py status /path/to/target-project

Delegated writer 기본 절차
==========================

1) classification -> routing_policy.py
2) task contract JSON 작성
3) workspace-local writer lock 획득

   python .codex/slt-tools/writer_lock.py acquire --task-id TASK-001

4) contract hash/validation/baseline 생성

   python .codex/slt-tools/contract_guard.py hash-contract --contract <contract.json> --write
   python .codex/slt-tools/contract_guard.py validate-task-contract --contract <contract.json>
   python .codex/slt-tools/contract_guard.py create-task-baseline --contract <contract.json> --json

   마지막 명령은 baseline 경로와 baseline_sha256을 반환합니다.
   Parent는 baseline_sha256을 보관하고 writer에게 전달하지 않습니다.

5) named writer 실행

6) parent가 parent-held seal로 write-set 검증

   python .codex/slt-tools/contract_guard.py verify-write-set \
     --contract <contract.json> \
     --baseline-sha <PARENT_HELD_BASELINE_SHA256>

7) parent가 결과를 수용한 후 lock 해제

   python .codex/slt-tools/writer_lock.py release --task-id TASK-001

기본 runtime state
==================

기본 lock과 baseline은 대상 worktree 내부의 다음 경로를 사용합니다.

   .codex/slt-state/locks/
   .codex/slt-state/baselines/

따라서 일반 Codex workspace-write가 .git 또는 ~/.codex 쓰기 권한 없이 생성할 수 있습니다.
Baseline 파일 자체는 workspace writer가 접근할 수 있으므로 filesystem secrecy에 의존하지 않습니다.
대신 parent-held SHA-256 seal이 baseline byte 변경을 탐지합니다.

SLT_STATE_HOME은 명시적으로 다른 writable state root가 필요한 경우에만 선택적으로 사용할 수 있습니다.

write guard는 tracked, non-ignored untracked, ignored untracked 파일을 검사하며 실제 filesystem casing도
반영하므로 Windows의 case-only rename도 탐지합니다. 매우 큰 disposable tree는 contract의
snapshot_exclude에 명시할 수 있지만 해당 경로는 보호 대상에서 제외됩니다.

주의
====

- Plugin 설치만으로 project custom agents가 자동 복사되지는 않습니다. setup 명령을 같이 실행해야 합니다.
- 동일 worktree에서는 writer_lock.py로 cooperating writer 1개만 운용합니다.
- writer lock과 baseline seal은 cooperative guard이며 악성 프로세스를 막는 pre-write ACL이 아닙니다.
- 병렬 writer가 필요하면 별도 Git worktree를 사용하고 DB/dev server/lockfile 등 공유 외부 리소스는 별도로 직렬화합니다.
- parent 모델은 skill이 강제로 변경할 수 없으므로 Terra High 세션으로 시작해야 합니다.
- semantic risk flag를 true/false로 판단하는 단계는 여전히 Terra/user의 근거 기반 판단입니다.
